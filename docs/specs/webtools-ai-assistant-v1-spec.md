>
> 文档版本：1.4。
>
> 创建日期：2026-07-17。

## 1. Executive Summary

### 1.1 Problem Statement

WebTools 的核心用户已经会使用 AI 编程工具，但尚未独立完成过从产品想法、网站搭建、功能开发到上线推广的完整流程。他们面临的主要问题不是缺少工具，而是信息过载、工具分散、阶段判断困难，以及无法将零散建议持续沉淀到同一个产品项目中。

立项时的资源助手只是一个简单的站内检索问答入口，缺少项目记忆、跨会话延续、可选联网搜索、专业 Skill、多模型选择、文件上下文和可持续的 Credit 计费能力。本规格对应的核心数据模型、接口和工作区现已实现，但模型渠道、搜索、支付和生产数据迁移仍须在真实环境验收。

### 1.1.1 Current Implementation Snapshot

截至 2026-07-19，代码层已实现：

- 用户可见模型与 Provider 配置解耦；
- 登录校验、请求并发限制、消息幂等占位和流式对话；
- Credit 预扣、滚动续扣、实际结算、退款与使用账本；
- 项目、项目对话、30 天回收站和项目记忆自动提炼；
- 全局记忆候选以 `pending` 状态保存，确认后才进入模型上下文；
- 站内知识检索、可选联网搜索、Skill 推荐与新对话继承；
- PDF、TXT、Markdown 解析分块，PNG、JPG、WebP 图片上下文；
- 文件解析、文件上下文和记忆上下文成本进入预计 Credit 与实际结算；
- 中英文 AI 工作区、服务条款和隐私政策初稿。

七个 V1 模型目前只作为后台目录记录写入，种子默认全部停用。视觉、推理和流式能力也默认关闭；管理员必须完成目标 Provider 实测并填写真实能力参数后，才能逐项开启能力和模型。

以下内容不能视为已验收：

- 五个 Claude 和两个 DeepSeek 精确模型 ID 的真实 API 可调用性、流式、视觉、推理、上下文和账单；
- 联网搜索 Provider 的生产账号、价格和故障行为；
- Creem sandbox／production 的真实支付、退款和拒付流程；
- 数据库迁移在生产数据副本上的演练；
- 全链路数据库并发、故障注入、安全和浏览器验收；
- 运营主体、联系邮箱、适用法律、退款政策和专业法律审阅。

### 1.2 Proposed Solution

建设一个独立的 WebTools AI 工作区，以大模型作为能力底座，默认结合 WebTools 站内知识库，并允许用户自主启用联网搜索和专业 Skill。用户可以将对话关联到具体项目，系统自动沉淀项目记忆，在新对话中继续理解项目进度并给出下一步建议。

AI 功能必须登录后使用。新用户获得 10 个有期限的赠送 Credit，后续通过 Creem 一次性购买 Credit。V1 不提供订阅，不按固定对话次数收费，而是根据模型、Token、联网搜索和文件上下文的实际成本进行预扣与结算。

### 1.3 Product Positioning

WebTools 整个网站继续保持现有「帮助建站新手找到每一步所需工具、内容和方法」的产品定位。

以下文案只用于 AI 助手介绍页或 AI 工作区，不替换整个网站首页定位：

> 把你的第一个 Web 产品做出来。

> 从想法、建站到上线，问 WebTools AI。

英文参考：

> Ship your first web product.

> From idea to launch, ask WebTools AI.

登录后的新聊天页面使用更直接的任务文案：

> 今天想推进哪一步？

> 告诉我你正在做什么，我会结合项目背景、工具和方法给你下一步建议。

### 1.4 Success Criteria

V1 上线后应满足：

1. 已登录用户可以使用 Claude 和 DeepSeek 完成流式多轮对话。
2. 站内知识问答能够引用真实资源、专题和文章，并显示来源。
3. 用户可以创建项目、关联对话，并在新对话中获得基于项目记忆的连续建议。
4. 用户可以主动启用联网搜索或「产品想法诊断」Skill，未启用时不产生对应成本。
5. 每次 AI 请求均经过 Credit 预扣、实际结算和退款流程，不允许余额透支或重复扣费。
6. 新用户只获得一次 10 Credit，赠送 Credit 30 天后过期。
7. 用户可以通过 Creem 一次性购买 Credit，支付成功后幂等到账。
8. 用户可以上传受支持的文件，并在回答中看到实际使用了哪些站内来源、外部网页和文件。
9. 所有项目记忆、全局记忆、聊天、文件和 Credit 记录都可以被用户查看或追溯。

## 2. Target Users

### 2.1 Core Persona

V1 主要服务以下用户：

- 处于 AI 编程初级阶段；
- 已经能够使用 Claude Code、Cursor 等 AI 编程工具；
- 尚未独立做出并上线过完整产品；
- 不熟悉从需求验证、设计、开发、部署到推广的完整流程；
- 面对大量工具、网站和社区信息时容易产生选择困难；
- 希望 AI 能持续理解自己正在做的项目，而不是每次从头解释。

### 2.2 Jobs To Be Done

当用户正在推进自己的第一个 Web 产品时，希望能够：

1. 快速确认当前阶段应该做什么。
2. 从 WebTools 内容中找到合适的工具、方法和资料。
3. 获得与当前项目背景相关的建议，而不是通用答案。
4. 在需要时启用联网搜索获取最新信息。
5. 在需要系统化判断时启用专业 Skill。
6. 将对话、文件、决定和进度持续沉淀到同一个项目中。

## 3. Product Principles

### 3.1 One Product, Different States

未登录、已登录有余额和已登录余额不足使用同一个产品骨架，不开发三套独立产品。不同状态只改变可用权限、提示内容和操作结果。

### 3.2 Default Simplicity, Advanced Choice

系统默认替初级用户完成模型和知识检索决策，同时为高级用户保留具体模型选择。普通用户不需要理解 API 提供商、Token 单价或底层路由。

### 3.3 User-Controlled Capabilities

联网搜索和 Skill 都必须由用户自主启用。系统可以推荐 Skill，但不能未经确认自动进入 Skill 流程或产生更高成本。

### 3.4 Traceable AI

回答中应明确展示实际使用的站内来源、外部网页和文件。项目记忆需要保留来源对话和来源消息，以支持删除、重算和纠错。

### 3.5 Cost Before Complexity

V1 使用 Credit 一次性充值，不引入订阅。先获得真实使用量、模型成本和用户复购数据，再决定是否增加月度 Credit 套餐。

## 4. Terminology

### 4.1 Chat

一条独立的多轮对话。对话可以不属于任何项目，也可以归属于一个项目。

### 4.2 Project

用户正在持续推进的具体产品或网站。一个项目可以包含多条对话、项目记忆、文件和 Skill 结果。

### 4.3 Project Memory

从项目对话中自动提炼的结构化精华，用于跨对话延续项目上下文。项目记忆不等于原始聊天记录。

### 4.4 Global Memory

不属于具体项目的长期用户信息，例如用户称呼、稳定偏好和反复出现的背景。系统可以先保存待确认候选，但只有用户确认后的记录可以进入模型上下文。

### 4.5 Skill

围绕特定任务组织的方法论、专属资料、追问流程、输出格式和结束条件。V1 用户界面统一使用「Skill」，不混用「专家」「Agent」等多个名称。

### 4.6 Provider

实际提供模型 API 的渠道。Provider 只在后台可见，普通用户只能看到模型名称和能力，不显示中转站名称。

### 4.7 Credit

WebTools AI 的统一使用额度。Credit 是用户侧的计量单位，不承诺与现金或固定 Token 数量一比一兑换。

## 5. Information Architecture

### 5.1 Public Website

未登录公开网站继续提供：

- 首页；
- 资源库；
- 行动专题；
- 文章；
- 公开作者主页（通过博客作者目录、文章作者入口和站内搜索发现）；
- AI 助手介绍；
- 登录入口。

资源、专题和文章无需登录即可免费浏览；收藏、项目关联、向 AI 追问、投稿和进度保存需要登录。

登录用户访问同一个首页地址时进入统一工作台，首屏以 AI 助手输入框为主要入口；工作台提供项目、聊天、公开内容和 Credit 等产品能力，不再显示营销落地页。

### 5.2 AI Workspace

AI 工作区至少包含：

- 新建聊天；
- 当前对话；
- 搜索聊天；
- 最近对话；
- 项目库；
- 项目详情；
- Skills；
- Credit 余额与充值；
- 全局记忆设置；
- 用户设置。

## 6. Authentication And Access States

### 6.1 Unauthenticated Visitor

未登录用户可以：

- 浏览全部公开资源、专题和文章；
- 查看 AI 助手介绍；
- 预览 AI 工作区界面。

未登录用户不可以：

- 实际发送 AI 请求；
- 创建项目；
- 保存聊天历史；
- 上传文件；
- 提交投稿建议。

用户在 AI 输入框发送内容时，应跳转或打开登录流程，并保留待发送问题，登录成功后可以继续。

### 6.2 Authenticated User With Credit

已登录且余额充足的用户可以使用 V1 全部 AI 能力：

- Claude 和 DeepSeek；
- 站内知识库；
- 联网搜索；
- Skill；
- 项目与项目记忆；
- 全局记忆；
- 文件上传；
- 历史对话；
- Credit 充值。

V1 不使用订阅权限墙，不要求用户先订阅才能使用某个模型或能力。

### 6.3 Authenticated User Without Enough Credit

余额不足时，用户仍可以：

- 查看和搜索历史对话；
- 查看项目、项目记忆和文件；
- 管理全局记忆；
- 查看已有 Skill 结果；
- 浏览公开内容；
- 进入充值页面。

余额不足时不能创建新的模型生成请求。

## 7. End-To-End AI Request Flow

一次请求的逻辑上下文为：

```text
用户问题
＋当前对话历史或摘要
＋当前项目的固定记忆
＋按需检索的相关项目记忆
＋WebTools 站内知识检索结果
＋用户选中的文件片段
＋可选联网搜索结果
＋可选 Skill 定义与专属资料
＋用户选择的模型
→ Credit 预估与预扣
→ 调用模型
→ 流式回答
→ 实际用量结算
→ 保存消息、来源、成本和记忆候选
```

站内知识库是基础能力，由系统根据问题自动判断是否检索，不作为用户开关。

联网搜索和 Skill 是附加能力，由用户自主启用。

## 8. Chat Requirements

### 8.1 New Chat

用户可以创建：

- 不属于项目的普通聊天；
- 属于某个项目的项目聊天；
- 使用某个 Skill 的 Skill 聊天。

一条对话最多属于一个项目。

### 8.2 Conversation History

系统完整保存原始用户消息和 AI 消息，包括：

- 文本内容；
- 消息状态；
- 模型；
- Skill；
- 是否使用联网搜索；
- 使用的站内来源、外部来源和文件；
- 输入、输出和缓存 Token；
- 预计、冻结、实际消耗和退款 Credit；
- 中断或失败原因。

### 8.3 Search And Resume

用户可以按标题和消息内容搜索自己的聊天，并重新打开继续对话。

历史对话必须按当前用户隔离，不允许通过猜测 ID 访问其他用户的内容。

### 8.4 New Project Chat Greeting

用户在已有项目中创建新对话时，系统应基于项目记忆主动展示：

- 上一阶段讨论了什么；
- 已经完成了什么；
- 当前阶段是什么；
- 建议下一步做什么。

该内容可以先以系统生成的项目摘要卡片呈现，不必立即产生一次收费模型调用；如果需要实时重新生成，则必须提前计入预计 Credit。

## 9. WebTools Knowledge Base

### 9.1 Citable Content

知识库至少覆盖：

- 已发布且允许 AI 引用的资源；
- 已发布且允许 AI 引用的专题；
- 已发布且允许 AI 引用的文章；
- 已发布且允许 AI 引用的关于我内容。

现有 AI 检索必须补充文章检索，并增加最低相关性阈值，不能在所有内容得分为零时仍强行提供无关来源。

### 9.2 Retrieval Behavior

系统应：

- 根据当前语言检索中文或英文内容；
- 优先返回与问题和当前阶段相关的内容；
- 只将达到最低相关性阈值的内容发送给模型；
- 无可靠来源时明确说明；
- 在回答中展示来源标题和站内链接；
- 不因检索失败而伪造来源。

### 9.3 Source Presentation

回答后按来源类型分组展示：

- WebTools 来源；
- 外部网页；
- 项目文件。

## 10. Web Search

### 10.1 User Control

联网搜索由用户在输入区主动开启，默认关闭。系统可以提示某个问题可能需要最新资料，但未经用户确认不能自动开启。

### 10.2 Cost And Transparency

启用联网搜索后：

- 预计 Credit 必须包含联网成本；
- 回答中必须展示外部来源；
- 外部来源和 WebTools 站内来源必须清晰区分；
- 搜索失败但模型继续回答时，应退回未实际发生的联网部分费用。

### 10.3 Search Provider

具体搜索服务商、API 和价格待实施阶段确认。供应商应由后台配置，不暴露给普通用户。

## 11. Skill Requirements

### 11.1 V1 Skill

V1 只上线一个 Skill：

> 产品想法诊断

整套产品、代码、文案和 Skill 内容中不得出现未经授权的人物姓名，也不得将 Skill 宣传为具体人物的官方观点或人格模仿。

收到原始 Skill 文档后，需要：

- 删除全部相关人物姓名；
- 删除人物模仿式提示；
- 将个人经验表达改写为中性方法论；
- 保留有价值的评估维度、追问流程和判断原则；
- 检查是否仍存在可识别原作者的描述；
- 记录 Skill 来源和使用权限，仅供管理员审计，不向用户宣传人物关联。

### 11.2 Skill Definition

一个 Skill 至少包含：

- 名称与简介；
- 适用场景；
- 不适用场景；
- 方法论资料；
- 初始系统提示；
- 固定诊断步骤；
- 需要向用户追问的问题；
- 快速初评输出格式；
- 深度诊断输出格式；
- 结束条件；
- 专属引用资料；
- 版本号；
- 发布状态；
- 是否允许用户使用。

### 11.3 Skill Lifecycle

- 一条对话最多启用一个 Skill；
- Skill 在该对话中持续生效；
- 用户可以关闭 Skill，回到通用问答；
- 用户不能在同一条对话中切换到另一个 Skill；
- Skill 可以持续多轮回答，直到用户结束或 Credit 不足；
- 对话应记录创建时使用的 Skill 版本，避免后续更新改变旧对话语义。

### 11.4 Skill Recommendation

普通助手判断问题适合某个 Skill 时，只能显示推荐：

> 这个问题适合使用「产品想法诊断」。

用户确认后：

1. 创建一条新的 Skill 对话；
2. 携带原始问题；
3. 携带所属项目的相关记忆；
4. 显示预计 Credit；
5. 完成预扣后开始 Skill 流程。

原普通对话继续保留。

## 12. Model And Provider Management

### 12.1 Planned V1 User-Visible Models

V1 计划首批开放：

- `claude-haiku-4-5-20251001`；
- `claude-sonnet-4-6`；
- `claude-sonnet-5`；
- `claude-opus-4-6`；
- `claude-opus-4-8`；
- `deepseek-v4-flash`；
- `deepseek-v4-pro`。

以上五个 Claude 模型均已出现在中转站公开价格页，但上线前仍须使用实际 API 验证可调用性、上下文上限、流式响应、工具能力和最终结算价格。

DeepSeek 官方文档在 2026-07-17 显示，`deepseek-chat` 和 `deepseek-reasoner` 将于 2026-07-24 15:59 UTC 弃用，因此 V1 规格直接采用 V4 模型 ID。接入前仍需通过官方 API 实测。

### 12.2 User Experience

完成目标 Provider 实测并由管理员启用后，界面计划提供：

- 自动选择；
- Claude Haiku 4.5；
- Claude Sonnet 4.6；
- Claude Sonnet 5；
- Claude Opus 4.6；
- Claude Opus 4.8；
- DeepSeek Flash；
- DeepSeek Pro。

模型资料表明 Claude Haiku 4.5 可能支持图片输入，但当前目标 Provider 尚未实测，因此种子仍将它与其余模型一样标记为不支持视觉。所有模型的视觉、推理和流式能力默认关闭，模型本身也默认停用；管理员完成真实 API 请求验证后再逐项开启。

种子中的 `contextWindow: 128000` 和 `maxOutputTokens: 8192` 只是未验证模型目录所需的保守配置占位，不代表目标 Provider 已确认支持这些上限。模型启用前必须按真实 API 能力更新。

普通用户不看到 Provider、中转站地址、API Key 或内部成本。

### 12.3 Provider Routing

后台必须将「用户可见模型」与「实际 Provider」解耦。每个模型可配置：

- 用户可见名称；
- 内部模型 ID；
- Provider；
- API Base URL；
- 加密保存的 API Key 或环境变量引用；
- 输入价格；
- 输出价格；
- 缓存价格；
- 上下文长度；
- 最大输出；
- 是否支持视觉；
- 是否支持工具；
- 是否支持流式输出；
- 是否启用；
- 排序和默认推荐模式。

管理员可以在不修改用户界面的情况下切换实际 Provider。

### 12.4 Provider Failure

当当前渠道失败时，不允许静默切换。V1 只提供：

- 仅本次切换到备用渠道；
- 不切换并退款。

切换前必须告诉用户：

- 备用模型或渠道是否仍为同一模型；
- 新的预计 Credit；
- 已产生的费用；
- 将继续生成还是重新发起请求。

未经用户同意不能切换，也不保存长期自动切换授权。

## 13. Project And Memory Requirements

### 13.1 Project Structure

项目至少包含：

- 项目名称；
- 一句话介绍；
- 目标用户；
- 当前阶段；
- 技术方案；
- 已确认决策；
- 已完成事项；
- 当前问题；
- 下一步待办；
- 重要结论；
- 最近进展；
- 相关对话；
- 相关文件；
- 相关 Skill 结果。

### 13.2 Project Memory Generation

项目内记忆自动生成，不逐次询问用户。每轮项目会话结束后，系统提取最有价值的信息并更新项目记忆。

项目记忆必须区分：

- 固定背景：产品简介、目标用户、当前阶段和关键决策；
- 进度信息：已完成事项、当前问题和下一步；
- 按需信息：技术方案、历史结论和相关细节。

每条记忆必须记录来源对话和来源消息，以便删除和重算。

### 13.3 Dynamic Memory Loading

每次回答不发送全部项目记忆：

- 始终携带项目简介、当前阶段和关键决策；
- 根据当前问题检索相关技术方案、结论和待办；
- 不携带无关旧内容；
- 项目记忆检索和压缩产生的模型成本应计入内部成本。

### 13.4 User Control

虽然项目记忆自动写入，用户仍可以：

- 查看全部项目记忆；
- 编辑错误信息；
- 删除单条记忆；
- 关闭项目自动记忆；
- 查看记忆来源。

### 13.5 Global Memory

项目外的普通聊天只识别长期、稳定、重复出现的信息，例如：

- 用户称呼；
- 稳定偏好；
- 反复提及的长期背景。

系统可以将识别出的长期信息保存为 `pending` 候选，但用户确认前不得标记为正式全局记忆，也不得进入模型上下文。一次性任务、临时事实和敏感信息默认不生成候选。

用户可以在设置中：

- 查看；
- 新增；
- 编辑；
- 删除；
- 关闭全局记忆。

## 14. File Upload Requirements

### 14.1 Supported Types

V1 支持：

- PDF；
- TXT；
- Markdown；
- PNG；
- JPG 或 JPEG；
- WebP。

V1 不支持：

- Word；
- Excel；
- PowerPoint；
- 音频；
- 视频；
- ZIP；
- 整个代码仓库。

### 14.2 Ownership

- 项目内上传的文件进入项目文件库，可供同一项目下不同对话复用；
- 普通聊天上传的文件只属于当前对话；
- 普通聊天文件不自动进入全局记忆；
- 从项目文件提取的重要结论可以进入项目记忆。

### 14.3 Limits

V1 默认限制：

- 单文件最大 20MB；
- 单次消息最多 5 个文件；
- 每个项目最多 50 个文件；
- 图片只在所选模型支持视觉时使用。

限制应由后台配置，后续可以调整。

### 14.4 Retrieval And Cost

- 每次回答只加载用户主动选择或系统判断相关的文件；
- 长文件必须先解析、分块和检索，只发送相关片段；
- 不能在每轮对话中重复发送整份长文件；
- 文件解析和模型上下文产生的 Token 计入本次 Credit；
- 发送前的预计 Credit 必须包含文件成本；
- 回答中显示实际使用的文件。

### 14.5 Storage And Privacy

- 文件默认私有；
- 文件存储复用项目现有 Cloudflare R2 能力；
- 对象路径不得使用可猜测的公开名称；
- 需要保存文件所有者、项目、对话、MIME、大小、哈希和解析状态；
- 文件、解析文本和检索索引只能被所属用户访问；
- 不得将用户文件加入其他用户或公共站内知识库；
- 不得宣称第三方模型不会训练用户数据，除非相应 Provider 条款已被验证。

## 15. Deletion And Recycle Bin

### 15.1 Delete Chat

删除项目对话时：

1. 对话立即停止参与检索；
2. 删除或重算由该对话产生的项目记忆；
3. 删除只属于该对话的文件和索引；
4. 保留 Credit 交易记录用于财务审计。

### 15.2 Delete Project

删除项目时，以下内容一起进入 30 天回收站：

- 项目；
- 项目聊天；
- 项目记忆；
- Skill 结果；
- 项目文件；
- 文件解析文本和检索索引。

回收站中的项目不参与 AI 回答。30 天内可以恢复，到期后永久删除。用户可以主动选择立即永久删除。

### 15.3 Permanent Deletion

永久删除后应清除业务数据、文件对象、解析文本和检索索引。为防止欺诈、拒付和重复领取赠送额度，法律或财务要求必须保留的最小交易、风控和审计记录可以继续保留，但必须与可恢复的用户内容分离。

## 16. Credit Business Model

### 16.1 V1 Monetization

V1 不提供订阅，只提供：

- 注册赠送 Credit；
- 一次性充值 Credit；
- 邀请注册和首次充值奖励 Credit。

所有已登录用户在余额充足时都可以使用 Claude、DeepSeek、联网搜索和 Skill，不设置额外权限墙。

### 16.2 Credit Types

#### Gift Credit

- 新用户注册成功后赠送 10 Credit；
- 每个自然人或风险身份原则上只能领取一次；
- 自发放之日起 30 天后过期；
- 不可提现、转让或退款。

#### Purchased Credit

- 通过 Creem 一次性购买；
- V1 暂定长期有效；
- 不自动续费；
- V1 提供 300、800 和 1,200 Credit 三档充值包。

V1 充值包确定如下：

| 套餐   | Credit | 美元价格 | 单 Credit 实付价格 |
| ------ | -----: | -------: | -----------------: |
| 入门包 |    300 |   $19.99 |            $0.0666 |
| 常用包 |    800 |   $44.99 |            $0.0562 |
| 进阶包 |  1,200 |   $64.99 |            $0.0542 |

常用包作为默认推荐档。充值包价格包含 Creem 固定手续费、支付费率和运营缓冲，因此套餐的单 Credit 实付价格不要求等于 AI 消耗公式中的 `$0.05`。`$0.05` 是请求结算时的 Credit 零售计价值，不是现金余额、兑付承诺或所有充值包的固定销售单价。

扣减顺序采用最早过期优先，赠送 Credit 通常先于长期有效的充值 Credit 消耗。

### 16.3 Pricing Formula

Credit 不固定等于一次对话。内部成本至少包括：

```text
模型输入成本
＋模型输出成本
＋模型缓存成本
＋联网搜索成本
＋文件解析或检索成本
＋必要的记忆提取成本
```

单纯把内部成本向上取整，不足以形成稳定的商业模型：低成本请求的毛利会异常高，高成本请求的毛利会逐渐接近零，也无法稳定覆盖 Creem 手续费、免费额度、失败重试、基础设施、汇率波动和供应商调价。

V1 采用「先加价，再向上取整」：

```text
内部成本美元
= 模型输入成本
＋模型输出成本
＋模型缓存成本
＋联网搜索成本
＋文件解析或检索成本
＋必要的记忆提取成本

零售成本美元
= max(
  内部成本美元 × 成本倍率,
  内部成本美元 ＋ 单请求最低毛利美元
)

原始 Credit
= 零售成本美元 ÷ 单 Credit 零售美元价值

最终 Credit
= ceil(原始 Credit)
```

因此，2.4 Credit 收取 3 Credit；3.0 Credit 只有在加价后的原始 Credit 大于 3 时才收取 4 Credit。不要使用「只要结果是整数就固定再加 1」的特殊规则。

同一次用户发送可能触发模型、搜索、文件解析或记忆提取等多个内部调用。用户侧按一次发送聚合结算并只执行一次最终取整，不能对每个微小内部调用分别向上取整，否则低成本模型会产生不合理收费。

V1 定价参数确定如下：

- 目标综合毛利率为 65%；
- 成本倍率为 `1 ÷ (1 - 65%) = 2.857143`；
- 1 Credit 的零售计价价值为 $0.05；
- 用户侧只显示整数 Credit；
- 每次成功发起的模型请求最低消费 1 Credit；
- 一次用户发送内部的多个成本项先合并，再进行一次最终取整；
- 联网搜索、文件解析等固定费用先加入内部成本，再统一加价和取整；
- Tavily 基础搜索按实际 1 个供应商 Credit 计入成本，高级搜索按实际 2 个供应商 Credit 计入成本；供应商 Credit 不是 WebTools Credit；
- 深度思考不另收拍脑袋的固定费用，推理 Token 按供应商实际输出用量计入模型成本；发送前使用推理预算提高预扣估算，完成后按实际用量结算并退回未用额度；
- 赠送 Credit、支付手续费和合理的平台故障成本由综合毛利覆盖，不在用户账单中单列；
- 模型价格、倍率、最低毛利和 Credit 面值必须由后台配置，不得硬编码在前端。

10 个注册赠送 Credit 对应 $0.50 的零售计价价值，但不代表现金余额，不可提现或兑换。该额度的体验目标是：足够完成至少两次标准 Sonnet 问答，或多次 Haiku、DeepSeek 问答，用完后用户已经感受到项目记忆、站内知识或 Skill 的价值。

### 16.4 Pre-Authorization

所有生成请求必须先预扣，不能先调用后扣费：

1. 根据模型、历史、项目记忆、Skill、联网搜索、文件和最大输出估算费用；
2. 检查余额；
3. 冻结首个 Credit 费用块；
4. 冻结成功后才调用模型；
5. 每个请求使用唯一结算编号，避免重试造成重复扣费。

### 16.5 Rolling Reservation

流式生成采用滚动预扣：

```text
首笔预扣成功
→ 开始流式生成
→ 冻结额度接近耗尽
→ 自动尝试冻结下一费用块
→ 余额充足则继续
→ 余额不足则终止当前请求并保留已生成内容
```

不要求用户在每次追加冻结前确认。滚动费用块和安全阈值由后台配置。

### 16.6 Settlement

请求完成后：

- 根据实际 Token 和附加能力成本结算；
- 退回未实际使用的冻结 Credit；
- 退款必须退回原 Credit 类型和原到期时间；
- 用户可查看预计、冻结、实际消耗和退回数量；
- 内部允许使用高精度成本，用户侧显示整数 Credit；
- 内部账本保留高精度美元成本和原始 Credit，用户余额与账单使用向上取整后的整数 Credit。

### 16.7 Insufficient Balance During Generation

余额不足时：

1. 终止当前模型请求；
2. 保留已生成部分；
3. 按已发生的实际 Token 结算；
4. 提示用户充值；
5. 充值后只提供「继续回答」；
6. 使用原问题、已有回答和相关上下文发起新的续写请求；
7. 新请求重新预扣并按新增 Token 收费。

系统应要求模型从中断位置继续，尽量避免重复已有内容。常规流式 API 无法真正暂停等待充值，界面中的「暂停」仅表示终止后可续写。

### 16.8 Failure And Refund

- 模型调用前失败：全额解冻；
- 用户主动停止：按实际用量结算；
- 能取得实际 Token 的中途失败：按实际用量结算；
- 无法取得用量的平台故障：默认全额退还；
- 平台故障造成的恢复生成：恢复成本由平台承担；
- 联网搜索未执行成功：退还联网部分；
- 平台重试不得向用户重复收取固定费用；
- 所有退款和补偿必须产生独立账本记录，不能直接覆盖历史交易。

### 16.9 Invitation Rewards

V1 对普通用户公开「邀请奖励计划」，暂不使用可提现佣金语义，也不对外称为联盟计划。邀请奖励只发放 WebTools Credit。

#### Valid Registration Reward

- 新用户必须通过有效邀请链接完成注册，并在注册后完成首次成功结算的 AI 请求；
- 邀请人获得 10 Credit；
- 被邀请人仍只领取系统原有的 10 个新用户赠送 Credit，不额外叠加邀请注册奖励；
- 注册奖励进入 24 小时待确认状态，通过基础风控后到账；
- 每位邀请人每个自然月最多获得 100 Credit 注册奖励；
- 单纯完成注册但未产生有效 AI 使用，不发放奖励。

#### First Purchase Reward

- 被邀请人完成首次 Credit 充值并通过支付确认与基础风控后，邀请人获得该套餐基础 Credit 数量的 10%；
- 只奖励被邀请人的首次充值，后续充值不重复返还；
- 奖励 Credit 向下取整为整数；
- 300、800 和 1,200 Credit 充值包分别返还 30、80 和 120 Credit；
- 节日赠送、人工赠送或其他奖励 Credit 不参与返还计算。

#### Attribution And Risk Control

- 邀请归因期为首次点击邀请链接后 30 天；
- 每名新用户只能归属一个邀请人，归属确认后不得更换或注册后补填；
- 禁止自我邀请、批量账号、虚假身份、关联支付账户和其他操纵奖励的行为；
- 退款、拒付、欺诈或订单撤销后，系统撤回或冻结对应邀请奖励；
- 邀请奖励不可提现、转让或退款；
- 注册奖励和充值奖励分别使用稳定幂等键，重复事件不得重复发放；
- 后台保留人工审核、撤回、冻结和解冻能力。

#### Holiday Campaigns

节日优惠不作为长期公开承诺，也不在当前价格页或邀请奖励页面提前展示。感恩节、复活节、黑色星期五、圣诞节等活动在实际开展时通过 Resend 邮件通知符合条件的用户。

内部计算规则为：

- 邀请充值奖励只按基础套餐 Credit 计算；
- 节日赠送 Credit 不参与 10% 邀请返还；
- 优惠券降低实付金额时不增加邀请返还数量；
- 是否允许优惠券与邀请奖励同时生效，由当次活动规则明确；
- 每次活动邮件或落地页必须披露优惠内容、适用套餐、有效期、使用次数和退款后的赠送 Credit 处理方式。

## 17. Abuse Prevention

预扣只能防止余额透支，不能单独阻止批量注册领取赠送 Credit。V1 至少需要：

- 只有完成 Google OAuth 或其他可信登录验证后才发放赠送 Credit；
- 用户只发放一次，删除账号后重新注册不能再次领取；
- 对用户、IP 和设备或浏览器风险标识分别限流；
- 同一设备或网络短期出现大量账号时暂停赠送；
- 赠送和充值 Credit 分开记账；
- 后台可以冻结异常账户、AI 功能或未使用的赠送 Credit；
- 对并发请求设置用户级上限；
- 防止多个并发请求同时透支同一余额；
- 拒付或恶意退款后冻结对应 Credit 和新的 AI 生成能力。

V1 不强制绑定手机号或银行卡，避免过高注册阻力。

## 18. Creem Payment

### 18.1 Payment Type

V1 只使用 Creem 一次性支付购买 Credit，不启用订阅、自动续费或月度 Credit 重置。

### 18.2 Existing Capabilities To Reuse

项目已有以下能力可复用：

- `src/extensions/payment/creem.ts`：Creem Provider；
- `src/app/api/payment/checkout/route.ts`：服务端价格读取、订单创建和 Checkout；
- `src/app/api/payment/callback/route.ts`：支付回调；
- `src/shared/services/payment.ts`：支付成功后生成 Credit；
- `src/shared/models/order.ts`：订单幂等处理；
- `src/shared/models/credit.ts`：Credit 发放、余额和到期优先扣减。

### 18.3 Required Changes

V1 需要：

- 将原 Pricing 套餐改造成 Credit 充值包；
- 只保留 `one-time` 产品；
- 充值成功后立即到账；
- 充值 Credit 的 `valid_days` 设为长期有效；
- 将成功返回页改为 Credit 余额或充值结果页；
- Webhook 和回调都必须幂等，不能重复发放 Credit；
- 支持后台配置 Creem sandbox、production、API Key、Signing Secret 和产品 ID；
- 配置 300 Credit／$19.99、800 Credit／$44.99 和 1,200 Credit／$64.99 三个一次性商品；
- sandbox 和 production 中三个商品对应的 Creem Product ID 仍需在 Creem 后台创建后回填。

### 18.4 Refund Rules

- 未消耗的充值 Credit 可以按照 Creem、适用法律和 WebTools 最终退款政策申请退款；
- 已消耗的 Credit 不退款；
- 赠送 Credit 不可退款或提现；
- 模型或平台故障的错误扣费自动退回 Credit；
- 拒付后冻结对应未消费 Credit 和新的 AI 生成能力；
- 用户仍可以查看或导出自己的历史数据；
- 后台支持人工补发、扣除、冻结和解冻 Credit。

## 23. AI Evaluation Strategy

### 23.1 Knowledge Retrieval Evaluation

建立覆盖建站阶段的测试问题集，至少包括：

- 需求验证；
- 设计；
- 前端开发；
- 数据库；
- 部署；
- SEO；
- 增长；
- 模型选择。

验收目标：

- 来源链接有效率 100%；
- 不相关来源不得被引用；
- 没有可靠来源时明确说明；
- 中英文问题返回对应语言内容。

### 23.2 Skill Evaluation

使用一组固定商业想法测试「产品想法诊断」：

- 快速初评覆盖预设评估维度；
- 信息不足时主动追问；
- 不伪造市场事实；
- 区分假设、证据和结论；
- 最终输出包含风险、验证方式和下一步；
- 全部输出不出现被删除的人物姓名。

V1 中性化 Skill 草案位于 `docs/skills/product-idea-diagnosis/`。产品运行时需要记录 Skill 版本，并将主流程与按需加载的专题参考分开，避免每轮携带全部资料。

### 23.3 Memory Evaluation

- 项目新对话能够正确复述上一阶段；
- 动态检索不携带明显无关记忆；
- 删除对话后相关记忆不再出现；
- 全局记忆候选未经确认不得进入模型上下文；
- 用户编辑记忆后下一次回答使用新值。

### 23.4 Credit Evaluation

- 无余额时模型调用次数为零；
- 并发请求不能造成负余额；
- 完成后实际扣费与 Token 账单一致；
- 未使用冻结额度正确退回；
- 失败、续写和故障切换不会重复扣费；
- Creem 重复回调不会重复发放 Credit。

## 27. Resolved Decisions

1. V1 面向会使用 AI 编程工具但未跑通完整产品流程的初级用户。
2. AI 使用平台统一提供的 API Key，不支持用户自带 Key。
3. 站内知识库默认按需检索，联网搜索和 Skill 由用户自主启用。
4. 首个 Skill 命名为「产品想法诊断」，不得出现未授权人物姓名。
5. 一条对话最多启用一个 Skill，不能在同一对话中切换 Skill。
6. Skill 推荐经用户确认后创建新对话，并继承原问题和项目背景。
7. 用户可以进行普通聊天，也可以将聊天关联到一个项目。
8. 项目内记忆自动写入；项目外全局记忆可以先保存待确认候选，确认前不得进入模型上下文。
9. 项目记忆动态加载，不在每次请求中发送全部记忆。
10. 删除项目进入 30 天回收站。
11. V1 支持 PDF、TXT、Markdown 和常见图片上传。
12. 文件存储不单独收费，解析和模型上下文成本计入 Credit。
13. V1 不做订阅，只做赠送 Credit 和一次性充值 Credit。
14. 注册赠送 10 Credit，30 天后过期。
15. 所有 AI 能力只受 Credit 余额限制，不设置额外付费权限墙。
16. 每次请求必须预扣，流式生成支持滚动续扣。
17. 余额不足时保留部分回答，充值后只能选择继续回答。
18. 平台故障造成的恢复生成费用由平台承担。
19. 模型故障后切换 Provider 必须获得用户本次同意。
20. 普通用户不看到 Provider，后台可以随时切换实际供应商。
