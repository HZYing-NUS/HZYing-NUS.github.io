# WebTools 登录分流、工作台与作者主页改版 PRD

## 一、文档信息

- 文档版本：1.0。
- 创建日期：2026-07-29。
- 需求澄清轮次：5 轮。
- 清晰度评分：94／100。
- 状态：需求已对齐，待设计与实施。

## 二、背景与目标

WebTools 当前首页、资源库、行动专题、文章、投稿和 AI 助手共用公开网站导航。用户登录后仍然看到营销落地页，缺少明确的产品工作台入口，AI 助手也没有成为登录后的首要任务入口。

本次改版参考 Semrush 登录前后分流和 Toolify 的内容发现方式，但不照抄其视觉或产品结构。改版目标是：

1. 未登录用户通过营销落地页理解 WebTools、发现公开内容并完成注册或登录。
2. 已登录用户访问首页时直接进入产品工作台，不再重复看到营销落地页。
3. 登录后首页以 AI 助手输入框为核心，帮助用户直接开始推进 Web 产品任务。
4. 公开内容继续承担 SEO、外部分享和建立信任的作用，登录后能力承担收藏、执行、项目沉淀和互动。
5. 博客同时承担文章发现和作者发现，但不新增网站一级“社区”导航。
6. 复用 ShipAny 现有账户资料路径、管理后台和 WebTools 已实现的社区资料能力，不重复建设相同系统。

## 三、目标用户与核心价值

目标用户是已经会使用 AI 编程工具，但尚未独立跑通完整 Web 产品流程的初级用户。

改版后的核心价值是：

- 未登录时快速理解 WebTools 能解决什么问题。
- 登录后不再浏览冗长介绍，而是立刻向 AI 描述当前任务。
- AI 回答能够继续引用站内资源、行动专题和文章，并引导下一步。
- 用户能够通过文章、作者目录或全局搜索发现其他用户及其公开主页。
- 用户只需填写少量信息，即可生成统一、可信的站内作者主页。

## 四、信息架构

### 4.1 未登录状态

未登录用户访问 `/` 时看到营销落地页。

公开导航保留：

- 首页；
- 资源库；
- 行动专题；
- 文章；
- 登录／注册。

公开导航不新增“社区”和“关于我”。

公开页面负责产品介绍、内容发现、SEO 和注册转化，不承载项目、记忆、文件、Credit 等产品能力。

### 4.2 已登录状态

已登录用户访问 `/` 时直接看到 WebTools 工作台首页。同一个首页地址根据登录状态渲染不同页面，不新增 `/home`。

工作台采用统一产品外壳：

- 左侧导航：主页、AI 助手、项目、资源库、行动专题、文章；
- 左侧底部或次要区域：投稿建议；
- 顶部：全局内容搜索、Credit、语言和用户菜单；
- 用户菜单：个人资料、我的公开主页、设置、退出登录；
- 不在登录后主导航显示“关于我”。

登录后首页包括：

1. AI 助手主输入框；
2. 快捷任务建议；
3. 最近项目和未完成进度；
4. 与用户阶段相关的资源、行动专题和文章推荐。

### 4.3 AI 与传统搜索分工

首页大输入框用于向 AI 提问：

```text
用户输入任务
→ 创建正式对话
→ 自动检索站内知识库
→ 生成回答并引用资源、行动专题和文章
→ 推荐下一步
```

顶部全局搜索用于直接查找：

- 资源；
- 行动专题；
- 文章；
- 用户。

AI 输入框和传统搜索必须保持为两个不同功能。

## 五、公开内容与登录权限

采用“公开阅读、登录后使用”的混合方案。

| 模块 | 未登录用户 | 登录用户 |
| --- | --- | --- |
| 营销落地页 | 完整查看 | 访问 `/` 时不显示 |
| 博客文章 | 完整阅读 | 阅读和互动 |
| 作者目录 | 浏览和搜索公开作者 | 浏览、关注和举报 |
| 作者主页 | 查看公开主页 | 查看、关注、举报和编辑自己的主页 |
| 资源详情 | 阅读核心内容 | 收藏、加入项目、向 AI 追问 |
| 资源库 | 浏览基础列表与分类 | 完整筛选、收藏和个性化推荐 |
| 行动专题 | 查看介绍、目标和步骤目录 | 查看完整步骤并保存进度 |
| AI 助手 | 展示能力与示例 | 正式提问并创建对话 |
| 项目、记忆、文件 | 提示登录 | 完整使用 |
| 投稿与修改建议 | 提示登录 | 完整使用 |

未登录用户打开受限能力时，应看到当前内容和明确的登录提示，不应无说明地跳转或显示空白页。

## 六、博客与作者发现

### 6.1 博客定位

博客仍然是网站一级导航，不新增“社区”一级导航。博客内部提供两个并列入口：

- 文章；
- 作者。

### 6.2 作者发现路径

用户可以通过三条路径发现作者：

```text
全局搜索 → 搜索用户 → 作者主页

博客 → 作者目录 → 浏览或筛选作者 → 作者主页

文章、评论等内容 → 点击头像、作者名或“查看主页” → 作者主页
```

用户不需要发布文章才能被发现。

### 6.3 作者目录收录条件

作者目录只收录满足以下条件的用户：

1. 用户主动发布公开主页；
2. 主页通过现有内容审核；
3. 主页未被管理员隐藏；
4. 至少具备公开用户名和显示名称。

仅注册但没有主动发布公开主页的账号，不进入作者目录和搜索结果。

作者目录支持按以下信息搜索或筛选：

- 显示名称；
- 公开用户名；
- 一句话介绍；
- 技能；
- 关注方向。

作者卡片可以展示头像、显示名称、一句话介绍、技能标签和文章数量。用户未填写的字段不展示。

V1 不开发复杂推荐算法。推荐作者和最近活跃排序可在获得真实数据后再评估。

## 七、作者主页

### 7.1 V1 承载方式

V1 只提供 WebTools 站内模板主页：

- 不支持用户上传或运行 HTML；
- 不支持作者主页自动重定向到外部网站；
- 不把外部个人网站作为作者主页的替代载体；
- 作者主页始终保留稳定的 WebTools 站内 URL。

### 7.2 表单字段

必填字段：

- 公开用户名；
- 显示名称。

推荐字段：

- 头像；
- 一句话介绍；
- 详细介绍。

可选字段：

- 经历；
- 技能；
- 作品；
- 所在地；
- 关注方向；
- 社交链接；
- 个人网站；
- 已发布文章；
- 公开内容夹。

除必填字段外，任何字段都可以不填写。未填写的模块必须自动隐藏，用户只填写显示名称也可以快速生成主页。

### 7.3 外部链接规则

作者主页允许展示 GitHub、个人网站、X 等普通外部链接，但必须满足：

- 只允许用户主动点击，不自动跳转；
- 明确标记为“外部链接”或显示对应平台名称；
- 使用 `target="_blank"`；
- 使用 `rel="ugc nofollow noopener noreferrer"`；
- 只接受合法的 `https://` 地址；
- 作为用户生成内容接受举报、审核、隐藏和下架；
- 不将外部链接作为搜索或推荐权重来源。

### 7.4 互动权限

- 未登录用户可以查看作者目录和公开作者主页；
- 关注作者、举报作者、编辑自己的主页必须登录；
- 用户主页公开后才进入作者目录和全局搜索；
- 主页修改继续使用“草稿、提交审核、旧版本继续展示”的现有流程。

## 八、现有路径与能力复用

### 8.1 ShipAny 账户资料路径

复用现有 `/settings/profile`，作为用户资料与公开主页设置的统一入口，不另建一套编辑路径。

现有职责包括：

- 登录账户名称；
- 头像；
- 公开用户名。

改版后在同一页面继续整合：

- 公开主页模板字段；
- 草稿保存；
- 提交审核；
- 查看自己的公开主页。

### 8.2 重复入口处理

现有 `/settings/community/profile` 与 `/settings/profile` 职责重叠。实施时应将公开主页编辑能力合并到 `/settings/profile`，并将旧路径重定向到 `/settings/profile`，保留旧链接兼容性。

### 8.3 公开作者主页路径

复用现有 `/u/[username]`：

- 保留用户名历史重定向能力；
- 保留 SEO 元数据和公开性判断；
- 使用本次全站改版后的统一 UI 重做页面呈现；
- 未填写的主页模块不渲染。

### 8.4 “关于我”迁移

- 公开导航和登录后主导航删除“关于我”；
- `/about` 永久重定向到梓颖自己的 `/u/[username]`；
- 原“关于我”内容迁入梓颖自己的作者主页；
- 旧文章的作者主页链接从 `/about` 改为梓颖自己的作者主页；
- 博客列表和文章详情统一展示头像、作者名和明确的“查看主页”入口。

梓颖的实际公开用户名需要在迁移执行前从生产数据确认，不允许在代码中猜测或硬编码错误用户名。

## 九、后台管理复用

继续复用 ShipAny 管理后台，不新建独立后台。

现有社区后台能力继续负责：

- 作者主页审核；
- 文章审核；
- 评论管理；
- 举报处理；
- 作者主页隐藏和恢复；
- 内容申诉；
- 审核邮件任务。

改版时需要补充：

1. 作者主页审核列表和详情入口更加明确；
2. 外部链接在后台可直接检查和下架；
3. 管理员可以按用户、用户名和审核状态搜索主页；
4. 管理员隐藏主页后，该用户从作者目录和全局搜索中消失；
5. 保留审计记录和权限校验。

现有 `/admin/profile` 是梓颖原“关于我”的结构化内容管理页。完成内容迁移后，应改为兼容入口或重定向至梓颖作者主页的后台编辑位置，不得与普通用户公开主页后台审核混为一谈。

## 十、UI 设计原则

整套页面必须和本次网站改版使用同一视觉系统：

- 登录前采用清晰、克制的营销落地页；
- 登录后采用统一工作台外壳；
- 作者目录、作者主页、博客列表和文章详情保持一致的排版、间距、颜色和交互规则；
- 吸收 Semrush 的任务优先级和导航克制感，不逐像素复制；
- 吸收内容社区清晰的作者露出和发现路径，不做信息拥挤的广场；
- 不把每个模块都包装成卡片；
- 桌面端和移动端都必须保留清晰的作者入口和 AI 主入口；
- 中文和英文界面同步实现。

## 十一、安全与边界

- 用户资料、关注、举报和编辑接口必须验证登录用户和资源所有权；
- 管理操作必须验证现有 RBAC 权限；
- 外部链接必须校验协议并安全转义；
- 不允许用户提交可执行 HTML、JavaScript、内联事件或任意 iframe；
- 用户生成内容必须经过现有审核流程后公开；
- 私有聊天、项目、文件和记忆不得进入公开作者主页；
- 未发布主页不得被公开搜索或索引；
- 被隐藏、删除或审核未通过的主页不得进入作者目录和搜索结果。

## 十二、与现有规格的差异

本 PRD 是当前任务对网站信息架构的最新明确要求。它会改变 `docs/specs/webtools-ai-assistant-v1-spec.md` 中以下旧描述：

- 已登录用户访问首页后仍使用公开网站骨架；
- 公开导航包含“关于我”；
- 资源、专题和文章全部无差别公开使用；
- AI 工作区仅作为独立 `/chat` 入口。

实施完成时必须同步更新 AI 助手 SPEC，避免代码和权威文档长期不一致。

## 十三、验收标准

### 13.1 登录分流

- [ ] 未登录用户访问 `/` 时看到营销落地页。
- [ ] 已登录用户访问 `/` 时直接看到工作台首页。
- [ ] 两种状态使用同一首页地址，不新增 `/home`。
- [ ] 已登录首页的首要动作是 AI 助手输入框。
- [ ] AI 输入框提交后创建正式对话。
- [ ] 顶部全局搜索与 AI 提问保持独立。

### 13.2 内容权限

- [ ] 未登录用户可以浏览公开文章、作者目录和作者主页。
- [ ] 资源核心内容可以公开阅读，收藏、加入项目和向 AI 追问需要登录。
- [ ] 行动专题公开介绍和步骤目录，完整执行和进度保存需要登录。
- [ ] 未登录用户触发受限操作时看到明确登录提示。

### 13.3 作者发现与主页

- [ ] 博客内部提供“文章／作者”切换，不新增网站一级“社区”导航。
- [ ] 未发文章但已发布公开主页的用户可以进入作者目录和搜索结果。
- [ ] 未发布公开主页的空账号不会被发现。
- [ ] 全局搜索可以返回用户结果。
- [ ] 文章列表、文章详情和评论中的作者入口统一指向 `/u/[username]`。
- [ ] 主页只要求公开用户名和显示名称即可发布。
- [ ] 未填写的经历、作品、技能等模块不会展示空状态。

### 13.4 路由复用

- [ ] `/settings/profile` 成为账户资料和公开主页编辑的统一入口。
- [ ] `/settings/community/profile` 重定向到 `/settings/profile`。
- [ ] `/u/[username]` 继续作为公开作者主页。
- [ ] `/about` 永久重定向到梓颖的公开作者主页。
- [ ] 旧用户名重定向行为不被破坏。

### 13.5 外部链接与安全

- [ ] 作者主页不会自动跳转到外部网站。
- [ ] 外部链接只接受合法 `https://` 地址。
- [ ] 外部链接使用 `target="_blank"` 和 `rel="ugc nofollow noopener noreferrer"`。
- [ ] 外部链接有明确的用户内容或外部链接标识。
- [ ] 用户不能上传或执行 HTML、JavaScript 或任意 iframe。

### 13.6 后台

- [ ] 继续复用 ShipAny 管理后台和现有 RBAC。
- [ ] 管理员可以审核、搜索、隐藏和恢复作者主页。
- [ ] 管理员可以处理作者主页和外部链接举报。
- [ ] 非管理员无法访问管理接口和页面。

### 13.7 质量验证

- [ ] 中文和英文页面同步完成。
- [ ] 检查未登录、已登录有余额、已登录余额不足三种状态。
- [ ] 检查桌面端和移动端。
- [ ] 运行 `pnpm lint`。
- [ ] 运行 `pnpm build`。
- [ ] 运行 `pnpm format:check`。
- [ ] 运行与社区资料、权限、搜索和路由相关的测试。

## 十四、实施阶段

### 阶段一：路由与数据职责收敛

- 明确 `/settings/profile`、`/settings/community/profile`、`/u/[username]`、`/about` 和 `/admin/profile` 的迁移关系；
- 确认梓颖生产环境的公开用户名；
- 补齐作者目录和全局用户搜索所需查询；
- 审查现有社区资料审核、隐藏和重定向测试。

### 阶段二：登录前后首页与工作台外壳

- 实现首页按服务端登录态分流；
- 建立登录后统一工作台导航；
- 将 AI 助手输入框作为工作台首页主入口；
- 增加快捷任务、最近项目和内容推荐区域。

### 阶段三：内容权限与统一布局

- 将资源、专题和文章接入确认后的公开／登录权限；
- 为受限操作增加登录提示；
- 让登录后的内容页面使用统一工作台外壳；
- 同步处理中英文和移动端布局。

### 阶段四：作者目录与作者主页

- 在博客内增加文章／作者切换；
- 实现作者目录和用户搜索；
- 重做 `/u/[username]` 模板；
- 合并公开主页编辑到 `/settings/profile`；
- 统一博客列表、文章详情和评论的作者入口。

### 阶段五：迁移与后台完善

- 将梓颖原“关于我”内容迁入个人作者主页；
- 配置 `/about` 和重复资料路径重定向；
- 完善作者主页审核、搜索、隐藏和举报处理；
- 更新 AI 助手 V1 SPEC 和部署检查文档。

### 阶段六：测试与发布

- 执行路由、权限、审核、搜索、外链安全和响应式测试；
- 运行 lint、构建和格式检查；
- 在预览环境验收中文、英文、登录前、登录后和余额不足状态；
- 确认旧链接、SEO canonical、sitemap 和重定向行为后发布。

## 十五、暂不包含

- 用户上传或运行 HTML 主页；
- 作者主页自动跳转外部网站；
- 私信；
- 独立动态广场；
- 复杂用户推荐算法；
- 用户等级、积分榜或创作者分成；
- 新建一套脱离 ShipAny 后台的管理系统。
