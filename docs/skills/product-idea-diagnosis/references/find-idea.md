# 寻找产品想法

## 适用场景

用户不知道做什么、想寻找 idea，或拥有技术能力但缺少真实问题时使用。

## 路径一：从重复抱怨出发

适合已经长期接触某个行业、岗位或社群的人。

1. 收集真实用户对重复任务、错误、等待和昂贵服务的原话；
2. 记录抱怨发生的具体场景、频率和当前替代方案；
3. 找出用户已经付出时间、金钱或风险的部分；
4. 先提供一次手工解决方案；
5. 有人付费后，再判断哪些步骤值得产品化。

优先寻找已经发生的行为，不让用户凭空想象未来需求。

## 路径二：从市场信号出发

适合转型者或暂时没有行业积累的人。可观察：

- 快速增长且具有使用意图的搜索词；
- 新平台、新 API 或政策变化带来的新工作流；
- 已经有人付费、但体验差或交付昂贵的产品；
- 依赖人工重复交付、具备标准化可能的服务；
- 创始人能够触达的细分群体。

市场信号只能生成候选想法，不能替代用户访谈和付费验证。

## 机会表

每个候选想法至少记录：

| 字段 | 要回答的问题 |
|---|---|
| 目标用户 | 第一个真实用户是谁 |
| 具体场景 | 最近何时发生过问题 |
| 当前方案 | 用户现在如何凑合 |
| 已付代价 | 时间、金钱、风险或机会成本是多少 |
| 最小交付 | 两周内能否手工完成一次结果 |
| 触达渠道 | 第一批 10 个用户在哪里 |
| 付费实验 | 第一次准备收多少钱 |
| 创始人优势 | 为什么由这个团队做更合适 |
| 最大风险 | 哪个假设一旦错误，项目就不成立 |

每次只推进一个候选想法，其余进入候选池，避免在多个方向之间反复切换。

## 危险信号

- 只谈市场规模，没有真实用户；
- 只说「大家应该需要」；
- 朋友说会用，但不愿投入时间或付款；
- 先选技术，再寻找可以套用的问题；
- 同时开发多个未经验证的方向。

## 下一步

今晚从一个熟悉的平台收集 20～30 条真实抱怨，保留原话，并标出重复出现且已经产生代价的问题。
