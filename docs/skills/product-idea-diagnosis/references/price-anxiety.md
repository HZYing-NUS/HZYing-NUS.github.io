# 定价与收费验证

## 适用场景

用户讨论定价、免费额度、按次、Credit、订阅、涨价或付费转化时使用。

定价必须同时考虑用户价值、替代方案、购买风险和交付成本。成本是价格底线，不是用户价值的上限。

## 先判断收费单位

选择与用户获得价值最接近的单位：

- 每次能得到独立结果：按次或 Credit；
- 使用量与价值同步增长：按量；
- 高频使用并持续沉淀数据或工作流：订阅；
- 依赖专家判断和定制交付：服务费或项目费。

不要为了收入稳定而强行订阅。先验证用户是否持续使用，以及持续使用是否持续产生价值。

## 购买理由强度

评估四项：

| 维度 | 强证据 |
|---|---|
| 后果 | 不解决会损失钱、时间、机会或承担风险 |
| 紧迫性 | 用户需要在明确期限前完成 |
| 重复性 | 问题每周或每月反复发生 |
| 付款行为 | 用户已经为替代方案投入预算 |

证据越强，价格越能接近用户获得的价值；证据越弱，越应该先缩小交付并做真实付款测试。

## 价格实验

1. 定义一个明确结果，不把功能数量当作价值；
2. 选择一个真实用户和触发场景；
3. 给出明确价格、交付内容和完成时间；
4. 要求真实付款或可退定金；
5. 记录接受、拒绝和犹豫的具体原因；
6. 修改定位或交付后再测试，不要只上下调整数字。

## 从服务到产品

可以按以下顺序降低人工比例：

```text
定制服务
→ 标准化报告
→ 半自动工具
→ 按次或 Credit 产品
→ 有持续使用证据后再考虑订阅
```

每一步都需要真实付款和重复使用数据支持，不能跳过验证。

## 危险信号

- 免费积累用户后再考虑变现；
- 只因为竞品便宜就更便宜；
- 增加功能后直接涨价，却没有增加结果价值；
- 用户说会订阅，但没有持续使用行为；
- API、退款、支付手续费和客服成本没有进入毛利测算。

## 下一步

选择一个具体用户，写清楚「结果、时间、价格、退款条件」，直接发出一次真实报价，并记录对方愿意支付或拒绝的原因。
