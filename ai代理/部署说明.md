# 「问问 AI」代理部署说明

这个文件夹是网站「问问 AI」功能的后端代理，跑在 Cloudflare Workers 上，唯一作用是**替你保管 DeepSeek 密钥**——这样密钥就不会出现在任何人都能查看的网页源码里。

网站本身（GitHub Pages）完全不用动，这个代理是独立部署的。

---

## 一、它是怎么工作的

```
访客浏览器  →  你的网页(index.html)  →  Cloudflare Worker(本代理)  →  DeepSeek
                                          ↑ 密钥存在这里，外人看不到
```

网页只知道代理的网址，不知道密钥；代理收到请求后，带着密钥去问 DeepSeek，再把回答转回网页。

---

## 二、首次部署（一次性，大约 15 分钟）

### 第 1 步：注册 Cloudflare 账号
打开 https://dash.cloudflare.com/sign-up 注册，免费。Workers 免费额度每天 10 万次请求，个人网站完全够用。

### 第 2 步：拿到 DeepSeek 密钥
1. 打开 https://platform.deepseek.com 注册并登录。
2. 进「API Keys」页面，点「创建 API Key」，复制那串 `sk-` 开头的字符串，先存好（页面关掉就看不到了）。
3. DeepSeek 是按用量付费的，需要在「充值」页面充一点钱（几块到几十块就能用很久，`deepseek-v4-flash` 很便宜）。

### 第 3 步：安装 wrangler（Cloudflare 的命令行工具）
确保电脑装了 Node.js（在终端输 `node -v` 有版本号即可）。然后：

```bash
npm install -g wrangler
```

> 不想全局安装的话，下面所有 `wrangler xxx` 都可以换成 `npx wrangler xxx`。

### 第 4 步：登录 Cloudflare
```bash
cd ai代理
wrangler login
```
浏览器会弹出授权页，点同意即可。

### 第 5 步：把密钥交给 Worker
```bash
wrangler secret put DEEPSEEK_API_KEY
```
终端会让你粘贴密钥，把第 2 步那串 `sk-...` 贴进去回车。这串密钥被加密存到 Cloudflare，**不会写进任何代码文件**。

### 第 6 步：部署
```bash
wrangler deploy
```
成功后终端会打印一个网址，形如：
```
https://ziying-ai-proxy.你的用户名.workers.dev
```
**把这个网址复制下来**，下一步要用。

### 第 7 步：把网址填回网页
1. 打开 `worker.js`，把顶部 `允许来源` 数组里的 `https://huangziying.github.io` 改成你真实的 GitHub Pages 域名（如果不一样的话），存盘后再跑一次 `wrangler deploy`。
2. 打开 `index.html`，搜索 `线上代理地址`，把那行的占位网址换成第 6 步拿到的 `https://...workers.dev`。
3. 把 `index.html` 推到 GitHub Pages。

完成。访客打开网站，右下角就有「问问 AI」了。

## 三、本地调试（改代码时用）

想在本机先试，不影响线上：

### 1. 给本地准备密钥
在 `ai代理/` 文件夹里新建一个文件 `.dev.vars`，写一行：
```
DEEPSEEK_API_KEY=sk-你的密钥
```
> 这个文件**不要提交到 Git**（已在 .gitignore 里忽略）。它只给本地的 `wrangler dev` 用。

### 2. 起本地代理
```bash
cd ai代理
wrangler dev
```
它会监听 `http://localhost:8787`。

### 3. 起本地网站
另开一个终端，在项目根目录：
```bash
python3 -m http.server 8000
```
浏览器打开 `http://localhost:8000`。网页里的代理地址会**自动**识别出你在本地，连到 `localhost:8787`，不用手改。

## 四、日常维护

- **改了主页资料怎么办**：如果你更新了 `内容配置.js`（比如新增一段经历），记得同步更新 `worker.js` 里的 `个人资料` 那段文字，否则 AI 答的还是旧内容。改完跑一次 `wrangler deploy`。
- **想调 AI 的性格/边界**：改 `worker.js` 里 `系统提示词()` 函数的文字，再 `wrangler deploy`。
- **觉得被人刷量**：调 `worker.js` 顶部的 `限流上限` / `限流窗口`（默认单 IP 每分钟 10 次），再部署。
- **看用量和花费**：DeepSeek 平台的「用量」页面能看消耗；Cloudflare 后台能看 Worker 请求数。

---

## 五、关于限流的提醒（进阶，可选）

当前限流用的是 Worker 的**内存计数**。Cloudflare 会跑多个 Worker 实例，内存不共享，所以这种限流只能挡住单实例上的突发请求，不是全局精确限流。对个人网站防滥用足够了。

如果哪天流量大、需要全局精确限流，可以改用 Cloudflare KV：
1. `wrangler kv namespace create 限流`，把返回的 id 填进 `wrangler.toml` 的 `[[kv_namespaces]]`。
2. 在 `worker.js` 里把 `超出限流()` 改成读写 KV 计数。

需要时再做，现在不用管。
